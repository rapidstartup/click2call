## T1. Call recording re-hosting (P1, depends on Phase C)
- **What:** Re-host or refresh Vapi recording URLs so the Pro tier's "Call
  recording (15 days)" promise is actually playable for 15 days.
- **Why:** Vapi returns expiring presigned S3 URLs. A `calls.recording_url`
  pointing at a dead link breaks the flagship analytics feature.
- **Context:** `calls.recording_url` + `transcript_ref` are in the Phase C
  schema. Vapi webhooks carry the recording URL at call end. Decide: copy to
  Supabase Storage (cost + complexity) vs refresh-token strategy (simpler).
- **Effort:** M. **Depends on:** Phase C `calls` table + webhook pipeline.

## T2. Wire mobile VOIP (P2, independent)
- **What:** Make the Expo app's call handling real instead of mocked.
- **Why:** `mobile/services/api.ts` returns hardcoded widgets/calls;
  `mobile/services/socketService.ts` emits `answer_call`/`mute_call`/etc. that
  `server/socket.ts` never handles. The app is scaffolding that promises more
  than it delivers.
- **Context:** Server `socket.ts:132` only handles `signal`, `call-start`,
  `call-end`. Mobile routes (`server/routes/mobile.ts`) register devices but no
  incoming-call flow exists. Full end-to-end VOIP is a dedicated feature, not a
  Phase A-D item.
- **Effort:** XL. **Depends on:** nothing, but sequencing it after the core
  browser flow ships avoids confusion.
